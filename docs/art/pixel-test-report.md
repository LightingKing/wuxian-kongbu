# 003 像素风格试验报告

结论：**Q 版像素玩法画面与动漫剧情立绘的组合可继续采用；当前流程先调整一致性，再批量生产。** 两套四动作图集、共享调色板、走廊背景及 Godot 演示已完成，尺寸、alpha、颜色和运行验证通过。动作语义可读，但跨状态的材质颜色、头部轮廓及细小标志仍有漂移，不能把工程验证通过写成美术已经适合无人复核地扩量。

## 生成与像素处理

只用 codex 登录渠道。每个角色先依据动漫参考生成独立 Q 版像素基础图，再运行 prepare → 原生 gen-set → extract → compose-atlas。人物约 2.5～3 头身；没有使用 pixel-draw、其他 provider、镜像或 RIFE。

统一 cell=48、logical_height=48、pixel_unfake=true、foot-centroid/bottom、ground_frames=true。每个 run 在首次 extract 前写入原生 `palette.lock.json`，颜色逐项来自 palette.hex；关闭 outline，防止量化后再次压暗轮廓产生额外颜色。`generate_facing_rows.py` 沿用 002 的薄接口方式，仅向原生 gen 转发 facing、regen 和非空 handed 参数，调度、参考图、分帧、抠图及合成仍由 sprite-gen 执行。

生成模型没有严格画出 32 格高的人物，pixel-unfake 的网格检测也出现谐波与分歧警告。初版站立帧约 35～40px。保留初版后，用原生 curation 对每个角色的所有帧统一 `scale=0.8, dy=3.2`，由原生 compose 最近邻变换到目标大小，脚底边界保持 y=40。没有逐帧拉伸到相同高度，没有改画人物。

用户明确补充：**按站立高度验收，倒地自然变矮**。下表保留倒地全过程的实际高度，不将其逐帧放大到站立高度。

背景的原图为 1672×941。安装版 sprite-gen 没有满足整张场景 kcentroid 缩小的命令，因此使用任务卡授权的 `pixelize_scene.py`：整画布区域划分、按数量加权的 RGB 二聚类、选择主簇，再映射到共享调色板；不裁切、不抖动、不做抠图。480×270 成品保留侧视研究所、墙面设施及下方约 38%～40% 开阔地面，无激光。

复现说明见 `art_src/pixel_test/README.md`；调色板用途见 `palette-notes.md`；生成阶段及朝向汇总见 `generation-summary.json`。

## 身份和动作

Godot 实际渲染的 [身份对照图](../../art_src/pixel_test/godot-identity-comparison-4x.png) 将原尺寸四倍像素人物与动漫设定图、平静立绘及丧尸参考并排。郑吒的黑短发、灰白衬衫、深裤和枪足以建立同一角色关联；丧尸的苍白皮肤、染血破白大褂、前倾姿态可以辨认为研究员丧尸。32px 不能可靠保留独特五官、手指或工牌文字；工牌本身在四倍下也不稳定，不能声称这些细节已锁定。

[完整逐帧 QA 板](../../art_src/pixel_test/godot-atlas-qa-4x.png) 保持原行列、Nearest 四倍显示。主审与独立复核未见明显额外肢体、反朝向或裁边。自动方向观察对郑吒 hit、丧尸 idle 返回 unknown；人工按脸部朝向、手臂与动作方向复核，维持郑吒朝右、丧尸朝左。没有因 unknown 执行镜像。郑吒 hit 的头脸更偏三分之四视角，严格侧视一致性仍需改进。

| 角色/动作 | 四帧可见高度(px) | 四倍下的语义与问题 |
|---|---|---|
| 郑吒 idle | 31 / 32 / 30 / 31 | 可辨小幅晃动；头发、肩形有逐帧变化 |
| 郑吒 attack | 29 / 28 / 29 / 32 | 抬枪→第 3 帧黄光射击→回收明确；第 4 帧比中间帧显高 |
| 郑吒 hit | 32 / 32 / 30 / 32 | 后仰与恢复可辨；头形变宽，裤子颜色偏紫棕 |
| 郑吒 down | 31 / 28 / 24 / 17 | 屈膝→撑地→横卧可读；后两帧枪与手不易分辨 |
| 丧尸 idle | 30 / 32 / 30 / 30 | 佝偻摇晃可辨；衣服亮块和头部轮廓略变 |
| 丧尸 attack | 32 / 32 / 31 / 32 | 前探伸手、扑咬意图可读；大褂衣摆仍有变化 |
| 丧尸 hit | 30 / 32 / 29 / 30 | 后仰/收身可辨，不能保证细部逐像素一致 |
| 丧尸 death | 32 / 27 / 21 / 11 | 跪地到横卧可辨；体块变化与网格检测警告需继续复核 |

枪在郑吒 attack 伸臂和火光帧最可靠，idle/hit 中只是少量黑像素，不能可靠确认双手握持。跨状态的位置也有差异，例如郑吒 hit 与 idle 的身体横向位置不同；共同脚底基线只保证垂直落地，不等于身体中心完全锁定。

固定调色板消除了调色板外的杂色，**没有消除配色分配变化**：郑吒 idle/attack 的裤子偏蓝黑，hit/down 偏紫棕；头发、脸宽、袖口与丧尸大褂的色块仍变化。不能据“共享 30 色”推导“没有闪烁”。本次实际验证证明动画推进、轮播和单次结束正常；静态逐帧审核证明动作语义可读，没有连续高帧率观察证据支持“过渡完全平滑、绝无闪烁”。

## 像素与运行验证

落盘 PNG 审计 `art_src/pixel_test/asset-audit.json` 记录逐帧矩形、bbox、颜色、alpha 和文件 SHA-256：

- 32 帧均 48×48，站立动作 28～32px；倒地按用户补充口径自然变矮。
- 所有帧最后可见像素行为 y=39，边界为 y=40；无空帧、越界矩形或被裁出的画布外透明补边。
- 两角色 alpha 仅 0/255，背景 alpha 仅 255。
- 郑吒实际 25 色，丧尸 23 色，背景 26 色；三者并集 **30 色**，调色板外颜色 0。
- 战斗截图排除顶部原生 UI 后，检查 115680 个 4×4 像素块，块内颜色不一致数为 **0**，证明该区域没有插值模糊或半格显示；记录在 `render-grid-audit.json`。

原生 inspect 两角色 errors 均为空，但保留 pixel-unfake 的网格检测、物理上限或安全余量警告。丧尸 score 总分 **94.75**，death **79**，其余三状态 100；**score 命令退出 1**。原因是 death 的 pitch disagreement/谐波检测，不是核心测试或 Godot 运行失败。未调低阈值、删除警告或把该评分写成通过；本次作为试验样本保留。

上述时间取自每张图片的原生 `elapsed_seconds`，不包含全部方向观察、后处理、人工复核、等待用户回答或 Godot 验证。两角色与独立状态并发运行，因此不能相加当作整次任务墙钟时间。成功图片未做方向重生。

丧尸基础图的模型实际返回 native alpha，但额外 chroma 后处理把发布图误删到只剩 93 个非零 alpha 像素。原生 raw 保留 304726 个非零 alpha 像素；检查后采用该未经改写的 raw 作为真正参考，保留坏输出证据。发现问题时已中断首次 idle/attack 两个行请求：只有空日志，无原图/完成报告，provider 是否完成及耗时未知；这 **2 个中断请求另列，不算作零调用，也不算生成成功**。有效批次在 `run-native/`，动作行未附加错误的透明后处理。

浏览器电脑操作因工具无法可靠识别当前 URL 而被停止，没有继续使用浏览器；本报告的视觉证据全部来自 Godot 渲染。工具 finish 的“保存全局默认值”是可选设置，未改变本机默认配置。

## 后续建议

保留当前 48×48、约 32px、两套画风和共享调色板方向。先固定每个角色真正 32px 的参考轮廓，锁定头部、裤子/白衣的具体材质色阶与横向锚点；让生成行减少网格密度漂移，避免反复依赖 physical cap。工牌和枪等识别物需要更明确的少量像素形状。每次仍保留四倍逐帧、GIF、量化审计与 Godot 检查，尤其复核死亡动作。

本次适合作为下一轮调整的流程基线；不建议按现状直接批量生成全部角色和敌人。
